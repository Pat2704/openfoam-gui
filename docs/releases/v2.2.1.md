# OpenFOAM Studio v2.2.1

**Validate BC no longer invents errors on cases that run.** A bug fix release,
found on a real snappyHexMesh case.

| | |
|---|---|
| **`OpenFOAMStudio-v2.2.1-folder.zip`** | **Recommended.** Unzip once, anywhere, then run `OpenFOAMStudio.exe` from the folder. About a second to the window. |
| **`OpenFOAMStudio-v2.2.1-portable.exe`** | A single file, nothing to unzip — at the cost of about half a minute at every launch, because the portable format unpacks the whole app into TEMP each time. |

---

## What was wrong

If a field addressed several patches at once — the ordinary OpenFOAM way of
writing it:

```
"splitter.*"
{
    type            noSlip;
}
```

the check read that key as the name `splitter.`, found no patch called that,
flagged the entry as an error, **and** reported all six patches it covers as
having no boundary condition. Thirteen invented errors per field, on a case that
meshes and solves.

## What it understands now

Every form a boundary key can take, because the survey is what the fix was
built from:

| | |
|---|---|
| `"splitter.*"` | a quoted regular expression — matched against the whole patch name, so `"wall"` does not silently swallow `outerWalls` |
| `splitter.*` | the same written without quotes. OpenFOAM reads it literally and it matches nothing; the panel resolves it as a pattern and tells you what it covers |
| `wall`, `walls` | a patch group, including the six-line `inGroups` list snappyHexMesh writes, and the group every patch has by virtue of its own type |
| `#include`, `#includeEtc` | preprocessor directives, which used to be parsed as a patch named `#include`. Reported as not checked |
| `$internalField` | a macro standing in for a whole entry |
| `//` and `/* */` | comments. A commented-out patch block was being read as a real one, and a brace inside a comment threw off everything after it |

Coverage follows OpenFOAM's own order — the patch's own name first, then a
group, then a pattern, with the last pattern winning. So a patch that has both
an exact entry and a pattern covering it shows the type the **solver** will use,
not the first one found.

## Two more, found while testing

- **Binary fields are read by OpenFOAM instead of by us.** `format binary;`
  writes half a megabyte of raw bytes between one patch entry and the next —
  braces and quotes included — and no text scanner survives it. Those fields go
  through `foamDictionary`, so `0/thickness` and friends are checked properly
  instead of losing every patch after the first block of data.
- **Multi-region cases are no longer checked against the wrong mesh.** Each
  region has its own patches; the previous fallback merged every region's
  boundary file, which made each region's patches look missing from all the
  others. It now says the case is multi-region and skips the patch check rather
  than reporting nonsense.

## And the panel reads better

A note is no longer printed in red when it is not a complaint. "via the pattern
`splitter.*`" is information about a healthy patch, and colouring it like an
error made a correct case look broken at a glance.

---

## Numbers

On the case this was reported from: **13 false errors per field → 108 checks
across 12 fields with zero errors**, in 5.4 seconds. Checked in the other
direction too — a deliberately broken field still reports a patch name that does
not exist, a pattern that matches nothing, and patches left without a condition.
The check did not get quieter, it got right.

## Upgrading

Replace the folder or the .exe. Nothing to migrate.
