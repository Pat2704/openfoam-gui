# OpenFOAM Studio v2.2

**This release stops the app telling you things that are not true of your
installation.** Three of the four changes are the same fix applied in different
places: read the answer off the OpenFOAM you actually have, instead of carrying
a copy of what some version of OpenFOAM looked like when the code was written.

| | |
|---|---|
| **`OpenFOAMStudio-v2.2.0-folder.zip`** | **Recommended.** Unzip once, anywhere, then run `OpenFOAMStudio.exe` from the folder. About a second to the window. |
| **`OpenFOAMStudio-v2.2.0-portable.exe`** | A single file, nothing to unzip — at the cost of about half a minute at every launch, because the portable format unpacks the whole app into TEMP each time. |

## The command list is read from your installation

The Commands tab used to show a list written by hand. Checked against the two
OpenFOAM installations it was meant to describe, **56 of its 103 entries did not
exist there** — `foamCalc`, `yPlusRAS`, `patchAverage` and the rest of the
post-processing utilities that OpenFOAM removed years ago, cfMesh commands that
are a separate product, and solver-module names that were simply wrong — while
**108 executables that are installed were missing from it**.

It now comes from your own installation: the executables in `$FOAM_APPBIN`, the
shell utilities beside them, and `foamToC`. That is 233 entries on OpenFOAM 14.
Each description is the one in that command's own source header, and the
categories are OpenFOAM's own directory layout, so neither can drift from the
version you are running.

Two things that fell out of reading the real thing:

- **Superseded solvers are listed, with what replaced them.** `simpleFoam` still
  exists on 13 and 14 — as a script whose only job is to tell you it "has been
  superseded and replaced by the more general incompressibleFluid solver
  module". There are 37 of those. They appear struck through, in their own
  category, because typing `simpleFoam` is exactly the question that script
  answers.
- **Solver modules are not executables**, so clicking one inserts
  `foamRun -solver <name>` rather than a name that would not run.

## The copilots say where an answer came from

FOAMy and the Claude agent already checked *names* against your installation.
What neither could do was explain what a command or an option actually does on
your build — so they answered from memory, which for OpenFOAM means from older
versions and from the ESI fork, and there was no way to tell.

A question about a command is now answered in three steps, in order, and the
reply says which one it rests on:

1. **your installation** — its command list, its run-time selection tables;
2. **the command's own `-help`**, run on your machine at that moment;
3. **the web**, and only if the first two found nothing.

So asking about `snappyHexMesh -overwrite` now gets you what your own binary
says — *"Deprecated option, this is now default behaviour"* — instead of a
recollection. And a name your version does not have comes back as "this does not
exist here, the closest names are…", with web sources listed separately and
labelled as such.

Two deliberate limits. A web query is built from OpenFOAM identifiers, never
from your message — the question stays yours. And results from ESI's
`doc.openfoam.com` are ranked below openfoam.org, CFD Direct and CFD Online and
flagged, because they dominate search results for almost every OpenFOAM term
while documenting a different fork whose syntax is often invalid here.

## `-overwrite` is gone from the quick commands

The quick command ran `snappyHexMesh -overwrite`, and the reference offered
`-overwrite` for eight utilities. It is deprecated on 13 and on 14 alike — each
binary's own `-help` calls it "Deprecated option, this is now default
behaviour". Overwriting the mesh is the default now; `-noOverwrite` is the
opt-out, and that is what the app suggests.

## Mesh tab

- **The vertex numbers refresh.** They were read from `blockMeshDict` once and
  then kept, so after editing the dictionary and re-meshing, Reload replaced the
  geometry and left the numbers describing the vertices the case used to have —
  and pressing the button again only hid and re-showed the same stale ones.
  Reload now clears them, so the next press reads the file again. Wireframe and
  the axes go back off with them: after a reload the toolbar means what it
  shows.
- **The axes are an orientation triad** in the bottom-left corner, with X, Y and
  Z on the arrows, instead of a set of lines standing at the case origin and
  resized to the model. It follows the camera, roll included.

## Upgrading

Nothing to migrate: replace the folder or the .exe. Your cases are untouched —
they live in WSL, not in the app.

The first launch after upgrading spends about two seconds reading the command
list from your installation, once, and caches it. It is re-read when you switch
OpenFOAM version.
