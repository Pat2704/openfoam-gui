# OpenFOAM Studio v2.3

**The Commands terminal now shows a command's output as it runs, reads it at a
glance, and stops leaving files behind.**

| | |
|---|---|
| **`OpenFOAMStudio-v2.3.0-folder.zip`** | **Recommended.** Unzip once, anywhere, then run `OpenFOAMStudio.exe` from the folder. About a second to the window. |
| **`OpenFOAMStudio-v2.3.0-portable.exe`** | A single file, nothing to unzip — at the cost of about half a minute at every launch, because the portable format unpacks the whole app into TEMP each time. |

---

## Output appears while the command runs

A foreground command used to show nothing until it finished. A `snappyHexMesh`
or a `checkMesh` that took a couple of minutes was indistinguishable from a
frozen app — you waited, and then the whole wall of text arrived at once.

Now the terminal streams: each line appears as OpenFOAM prints it, with a
spinner and a live cursor while the command is still going. The view follows the
newest line on its own, and steps aside the moment you scroll up to read
something — a **follow output** button brings you back to the bottom when you
want it.

## It reads like a log, not a wall of red

Before, a command that failed turned its *entire* output red — the two hundred
lines of banner and progress exactly as red as the three lines that told you
what went wrong. Now the block is neutral and the lines that matter carry the
colour:

- `--> FOAM FATAL ERROR` and `FOAM Warning` stand out;
- the `Time = ` clock is highlighted, so you can find your place scrolling a long
  solver log;
- the startup banner every OpenFOAM tool prints is dimmed into the background;
- the exit status shows as `exit 1` in the header, and only the left edge of the
  block is tinted by success or failure.

## Background commands no longer invent a log file

Ending a command with `&` runs it in the background. It used to have
` > log.<command> 2>&1` silently bolted on, so `foamRun &` created a file you
had not asked for and did not know the name of. Now a background command gets
exactly the redirection you wrote — and if you wrote none, the terminal tells
you its output is going nowhere and how to capture it, rather than quietly
deciding for you.

The confirmation for a background command is also correct now: it reports the
real process id, which the Monitor tab picks up so you can follow the run there.

---

## Upgrading

Replace the folder or the .exe. Nothing to migrate — your cases live in WSL, not
in the app.
