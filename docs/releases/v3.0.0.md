# OpenFOAM Studio v3.0.0

**An audit of the whole application, and what it found.** The agent could get a
shell it was not supposed to have, a command aimed at a renamed case ran
somewhere else, and saving a file could destroy it. All three are fixed, along
with a good deal else. A major version because the security model actually
changed.

| | |
|---|---|
| **`OpenFOAMStudio-v3.0.0-folder.zip`** | **Recommended.** Unzip once, anywhere, then run `OpenFOAMStudio.exe` from the folder. About a second to the window. |
| **`OpenFOAMStudio-v3.0.0-portable.exe`** | A single file, nothing to unzip — at the cost of about half a minute at every launch, because the portable format unpacks the whole app into TEMP each time. |

---

## Security

Four of these change what the app is able to do, so they are worth reading even
if you only ever use it on your own machine.

**The Claude agent could escape its guard rails.** `Allrun` is on its list of
allowed commands, and running one executes it as a shell script — and the agent
could also *write* that file. Two individually-permitted calls therefore added
up to an arbitrary shell: write `Allrun`, then run it. The claim that "`rm -rf`
is not expressible" was simply false. It may still run a tutorial's own `Allrun`;
it may no longer author one.

**Command arguments were never checked, only the command.** Every OpenFOAM
utility understands `-case <dir>`, so an allowed executable could be pointed at
anything on the disk — `checkMesh -case /mnt/c/Users` was permitted. Arguments
are now resolved and must land inside the run directory. A sibling case
(`mapFields ../coarse`) still works, because that is inside it.

**The agent's tool endpoint was unauthenticated outside the packaged app.** An
empty token *skipped* the check rather than failing it, and only the packaged
app set one — so under `npm run dev` any local program that found the port could
drive your cases. It fails closed now.

**Any web page you visited could send commands to the app.** The interface talks
to `127.0.0.1`, and a browser lets any site send requests there; an `<img>` tag
pointing at the right URL was enough to kill every running solver. Requests the
browser reports as coming from another origin are now refused.

Also: choosing an OpenFOAM version accepted any path and then sourced it into
every later command; it must now be one the app itself detected.

## Things that were quietly wrong

**A failed `cd` did not stop the command.** Because of how the shell line was
assembled, a command aimed at a case that had been renamed or removed ran anyway
— in whatever directory the shell happened to start in. With the guard rails off
that is the difference between an error and losing files.

**Saving a file could destroy it.** The write truncated the target before it had
any replacement content, so anything interrupting it — WSL restarting, a
timeout, a full disk — left an empty file and the old content gone. Saves are now
atomic: the file is either wholly the old version or wholly the new one. It also
keeps the file's permissions, so editing a case's `Allmesh` no longer stops
`Allrun` from being able to call it.

**One momentary WSL hiccup could break the session.** If WSL was still starting
when the app first looked, the app remembered "no OpenFOAM here" permanently:
every command then ran without the environment and failed with
"blockMesh: command not found" until you restarted it. Failures are no longer
cached.

**The residual chart stopped working on long runs.** It read the entire log on
every refresh and, past a certain size, reported the failure as "Log not found".

**A background run that failed to start reported success**, and left three files
behind in `/tmp` every time. `decomposePar` never appeared in the Monitor — the
process list was looking for a misspelt name.

**Boundary-condition validation checked files that are not boundary conditions.**
On a snappyHexMesh case, `0/` also holds `cellLevel`, `pointLevel`,
`nSurfaceLayers`, `thickness` and `thicknessFraction`, written by the mesher.
They look like fields and are not physics; they are skipped now.

## Interface

**Scrolling no longer lags.** Two causes, both real: the scroll areas drew their
own scrollbar from JavaScript, always a frame behind the content; and they were
scroll containers even when they had nothing to scroll, so the wheel had to
travel through them before reaching the page. Both are gone — scrolling is the
browser's own now.

The window is also used properly: the header, tabs and status bar stay put and
the content scrolls beneath them, so a long file tree or command list no longer
pushes the navigation off the screen.

**The colours mean something now.** The same palette as before, but each colour
is defined once and has a correct value in both light and dark — several were
dark-mode values being shown in light mode, and vice versa. Small text on tinted
backgrounds now meets WCAG AA in both themes; the worst case before was 2.99:1.

Smaller things: deleting a file asks first, and switching file no longer discards
unsaved edits without a word; `Ctrl+S` no longer reports success before the save
has happened; `Ctrl+B` switches the theme back as well as forward; a confirmation
dialog no longer silently cancels the next one queued behind it; and links in
FOAMy's replies are visible, which they were not.

## Under the hood

The project has tests for the first time — 95 of them, covering the input
validators that everything reaching WSL passes through, and the case generator,
whose output has to satisfy two incompatible OpenFOAM layouts. They run on
`node --test` with no framework to install and no build step.

Two of the bugs above were found by writing those tests.

## Upgrading

Replace the folder or the .exe. Nothing to migrate, and no settings change —
your API key and OpenFOAM version selection are kept.
