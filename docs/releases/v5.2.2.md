# OpenFOAM Studio v5.2.2

**The case switcher, the built-in agents and the residual plots now all agree
with what is actually there.**

| | |
|---|---|
| **`OpenFOAMStudio-v5.2.2-folder.zip`** | **Recommended.** Unzip once, anywhere, then run `OpenFOAMStudio.exe` from the folder. |
| **`OpenFOAMStudio-v5.2.2-portable.exe`** | A single file, nothing to unzip. It extracts into TEMP on each launch. |

## The case shortcuts follow the cases

- Deleting a case left its shortcut in the header, offering a case that no
  longer existed — and, when it was the open one, added a nameless shortcut
  beside it.
- Changing the OpenFOAM version or the WSL distribution left the previous
  installation's cases up there too, although its run directory is a different
  one.
- The shortcuts are now checked against the case list whenever it changes, so
  every route to a vanished case — delete, rename, a version switch, an agent
  removing one — closes its shortcut.

## Claude and Codex follow the case you switch to

- Switching case from the header shortcuts was only communicated to a running
  conversation through the instructions the app rebuilds each turn. Against a
  conversation full of the previous case — its files, its mesh, its logs — that
  loses, and both agents went on working on the case you had left.
- The app now says so in its own voice, as it already does when the
  guarded/unrestricted mode changes: the new case is named, the old one is
  named, and what the agent learned about the old one is marked as belonging to
  it. FOAMy is told as well.

## Residual plots that match the log

- The Monitor drew residuals against a fixed 1e-8 to 1 axis and clipped
  anything outside it, so a run starting above 1 was flattened onto the top edge
  and a well-converged one was crushed against the bottom. The axis now spans
  the decades the log actually contains. A run restarted from a later time no
  longer has its whole history squeezed against the right-hand edge either.
- A residual of exactly zero — what OpenFOAM writes for a field it did not solve
  on that step — cannot be placed on a logarithmic axis; those points are gaps
  now, rather than lines diving to the floor.
- In Post-Process, **log Y** refused to switch on if a single sample anywhere in
  the dataset was zero or negative, which for many runs meant it never worked.
  It is available whenever there is something to draw logarithmically, and says
  how many points it has to leave out.

## Charts you can shape before saving them

- The Post-Process chart can be panned by dragging, zoomed with the wheel
  (Shift for the time axis alone, Alt for the value axis), fitted again with a
  double-click, and resized by its bottom-right corner. **Reset view** puts it
  back.
- The export preview takes the same gestures, and it is the file itself: what
  you pan, zoom and resize there is what gets written, at the size the corner
  handle gives it.

## Smaller things

- Choosing a ParaView filter and then deleting what it created left the filter's
  name in the picker, and choosing it again did nothing until something else had
  been picked in between.

## Compatibility

Windows 10/11 with WSL2 and OpenFOAM Foundation v9-v14. ParaView remains an
optional local integration. OpenFOAM and AI model weights are not bundled.
