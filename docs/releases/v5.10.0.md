# OpenFOAM Studio v5.10.0

**Multi-region cases work across the app: Monitor sees `foamMultiRun`, and every tab finds each region's mesh, fields and results.**

| | |
|---|---|
| **`OpenFOAMStudio-v5.10.0-folder.zip`** | **Recommended.** Unzip once, anywhere, then run `OpenFOAMStudio.exe` from the folder. |
| **`OpenFOAMStudio-v5.10.0-portable.exe`** | A single file, nothing to unzip. It extracts into TEMP on each launch. |

## Multi-region cases

A multi-region case keeps each region in its own folders:
`constant/<region>/polyMesh`, `0/<region>/`, `system/<region>/` and
`postProcessing/<region>/`. Most of the app looked only at `constant/polyMesh`
and `0/`. The app now finds the regions the way OpenFOAM does: from
`regionSolvers` in `controlDict` (v11 and later), from
`constant/regionProperties` (v9/v10), or from the meshes that exist.

- **Monitor.** The app recognised a run only by a fixed list of solver names,
  and `foamMultiRun` was not on it. A running case showed as idle, and
  **Kill case** could not stop it. Any OpenFOAM executable is now recognised,
  whatever the version, including solvers you compiled yourself.
- **Residuals.** `film Ux` and `fluid Ux` were drawn as one curve. Each region's
  fields are now separate (`film/Ux`, `fluid/Ux`…).
- **Simulated time.** Monitor read the clock time instead of the simulated
  time, on every case, not only multi-region ones. It now shows the simulated
  time.
- **Mesh tab.**
  - checkMesh runs on every region and combines the results into one report.
  - The 3D view shows all regions with their patches.
  - Boundary conditions are checked for each region against its own mesh.
- **ParaView.** The case opens with every region, and each part is labelled
  with its region. Before, the case was refused as having no mesh.
- **Post-Process.** Results under `postProcessing/<region>/` are listed and
  read. A new **Region** selector builds the command with `-region` and that
  region's solver module.
- **Commands.**
  - Running the case uses `foamMultiRun`.
  - checkMesh has one button per region.
  - `decomposePar` and `reconstructPar` use `-allRegions`.
- **Dashboard.** File counts include the region folders.
- **Agent.** Its log, mesh and field analyses keep the regions apart.

## A preflight without false notes

The File Editor's **Preflight** gave a multi-region case more than a dozen
"not verified" notes. Almost all of them were wrong; on a film case, one
remains: checkMesh was not run.

- **Large initial fields.** Fields over 128 KB were skipped because of their
  `nonuniform` values. They are now read without those values, so their
  headers and boundary conditions are checked.
- **`#includeEtc "caseDicts/setConstraintTypes"`.** Fields that include this
  file were reported as only partly checked. The include is now read from the
  installation, as OpenFOAM reads it. This also applies to the boundary
  condition check in the Mesh tab.
- **Names wrongly reported as unknown.**
  - A model inside a boundary condition, such as a film's
    `contactAngle { type constant; }`, is no longer taken for the condition
    itself.
  - Lagrangian models such as `coneInjection` and `rebound` exist, even though
    `foamToC` does not list them.
- **OpenFOAM libraries.** A library that ships with the installation, such as
  `liblagrangianParcel.so`, is no longer reported as custom code. A library the
  installation does not have is, by name.
- **Checks for each region.** The preflight warns when a region has no
  `system/<region>/fvSchemes`, no `fvSolution` or no fields in `0/<region>/`.

## Compatibility

Windows 10/11 with WSL2 and OpenFOAM Foundation v9-v14. All v5.9.4
functionality is included. The v9/v10 multi-region layout
(`chtMultiRegionFoam`) was checked against test data only.
