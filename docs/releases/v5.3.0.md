# OpenFOAM Studio v5.3.0

**Every function object the installation offers, explained and called the way
OpenFOAM actually reads it — and a ParaView tab that no longer makes you wait
for its first start.**

| | |
|---|---|
| **`OpenFOAMStudio-v5.3.0-folder.zip`** | **Recommended.** Unzip once, anywhere, then run `OpenFOAMStudio.exe` from the folder. |
| **`OpenFOAMStudio-v5.3.0-portable.exe`** | A single file, nothing to unzip. It extracts into TEMP on each launch. |

## Post-Process: the calls now run

The **Compute…** panel was checked against the installed OpenFOAM 14 and 13 —
their own parsing code, every template, and a real replay of each of the 127
v14 function objects on a solved case. 61 of those calls failed before this
release; the ones that failed because of the app no longer do.

- **Forces, y+, wall shear stress.** Replaying a function over finished times
  built no turbulence or transport model, so drag and lift coefficients,
  `yPlus`, `wallShearStress`, `turbulenceIntensity`, `wallHeatTransferCoeff` and
  `power` stopped with "No valid model for viscous stress calculation". The
  command now carries `-solver <your solver>` whenever the case names one and
  your OpenFOAM supports it, and the panel explains what it changes.
- **Examples made of your case.** Patches, fields and zones the case really has,
  a sampling line that crosses the mesh instead of running from the origin to
  the origin, a direction that is a direction, the other patch for the second
  side of a difference, and list values that keep the brackets OpenFOAM needs.
- **Every option, correctly labelled.** Help text is attached to the entry it
  describes — several functions were showing another entry's explanation — and
  the options the templates offer commented out (`distance`, `weightField`,
  `phase`, `writeFields`, `extrapolate`, …) are listed as options instead of
  being lost. `writeMesh` asks for the `writeControl` it needs.
- **The full reference for each function.** Beside the template, the panel now
  shows the documentation OpenFOAM ships with the class behind it: what it does,
  a complete dictionary example, and the table of every entry with whether it
  is required and its default — read from your installation, so it matches your
  version. It also says where the output lands, which times are on disk, and
  which libraries the function loads.
- **Your own function objects.** Ones you keep under `~/.OpenFOAM` were listed
  by OpenFOAM but refused by the panel as unavailable. They are offered now.

## ParaView starts warm

- The first ParaView start after a reboot took a minute or more: Windows was
  reading hundreds of ParaView's libraries off the disk, scanning each one.
- A few seconds after the app opens, it now loads ParaView once in the
  background at low priority — the Dashboard card shows **warming up** — so by
  the time you open the ParaView tab it starts in seconds. The switch is in the
  Dashboard's ParaView settings.

## Compatibility

Windows 10/11 with WSL2 and OpenFOAM Foundation v9-v14. ParaView remains an
optional local integration. OpenFOAM and AI model weights are not bundled.
